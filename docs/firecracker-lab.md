Every actual invocation creates a fresh private session and immutable outer image. Eight capabilities are fixed: CHOWN, DAC_OVERRIDE, SETUID, SETGID, SYS_CHROOT, MKNOD, SYS_ADMIN, KILL. The only added device is `/dev/kvm` with rw permission. There is no device-cgroup wildcard, TUN rw permission, NET_ADMIN, NIC or host namespace. The trusted outer uses the approved unconfined LSM/seccomp exception; Firecracker's official filter remains enabled. Jailer may create TUN/urandom/userfaultfd device nodes; node creation is distinct from device-open authority. Docker device additions are not its full effective policy: the prior source772 actual attempt opened a private TUN inode and stopped before worker/VMM startup. The fixed `warden-tun-deny-v1` cgroup-device BPF program adds only a char10:200 READ/WRITE denial. MKNOD-only and other devices remain governed by the original runtime policy. Its14 immutable instructions/112 bytes have SHA256 `bd958d0d3ab7193f91cb14013f9ce53ddd88c46ab6cba89337b7e4eeb6e74404`, bound into the manifest/policy hash. It uses the existing SYS_ADMIN authority, raw ALLOW_MULTI attachment, no maps/helpers/loops, no override/replace/detach/link/pin, and exact original direct/effective ID preservation. Any permission/query/attach/probe uncertainty stops without retry or expanded authority; no actual BPF enforcement is claimed by unit tests.

The sole session bind is the fixed realpath of a fresh UID1000/mode0700 directory, initially RO/rprivate. The host retains its original nofollow FD and rechecks dev/inode/UID/mode before create and start. Before accessing session contents or changing devices/cgroups, the supervisor checks the held identity, a distinct private mount namespace, unique mount ID and device, no propagation/submounts, and bounded VFS flags. Every privileged mode emits a fixed4KiB-max receipt and waits at most10s for the single literal `WARDEN_DEVICE_RECEIPT_OK\n` followed by EOF before BPF load; it closes that channel before further work. The host uses the exact owned CID/immutable image/Running PID, pidfd, nofollow proc metadata/starttime/NSpid and measured systemd cgroup path to match the retained host cgroup FD dev/ino to the trusted outer receipt. After additive policy proof and device probes, only the live supervisor removes RO through its held container FD and rechecks the same mount ID and every other flag; filesystem super-options are separate. Supervisor PID1 also authenticates the private cgroup namespace, exact outer limits and read-only root/proc-sys before creating the fixed private subtree. Each VMM uses foreground jailer, a distinct durable monotonic host UID/GID in 2000000001..2001000000, an original pidfd and a captured cgroup. Shared read-only assets are never chowned. The guest agent mounts the SHA-bound payload disk read-only and launches UID/GID65534 with no_new_privileges, no capabilities, a separate cgroup and a default-deny filter that blocks the control-vsock family. Trusted framed vsock metrics are separate from bounded tenant stdout. Lost EXEC is never retried.

All six privileged modes retain `container create --interactive` and `container start --attach --interactive`.
