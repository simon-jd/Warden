Its [mountViaFds](https://github.com/opencontainers/runc/blob/v1.5.2/libcontainer/mount_linux.go) invokes the mount syscall directly when no special source FD is supplied, consistent with this error's absence of srcFile detail. [handle_dots](https://github.com/torvalds/linux/blob/v7.0/fs/namei.c) leaves a final `.` on that same path; appending `/.` does not relocate the mount reference.

This is a source-supported explanation of the observed error, not a syscall trace or a claim that the Ubuntu kernel source is byte-identical to upstream7.0. The exact installed runc version and pinned upstream file hashes are recorded in `sources.json`. No `/.` workaround is claimed or tried. ## Explicit controller ruling and implemented handshake

The controller explicitly accepted an equivalent end-to-end identity constraint in place of a literal host FD Source. This was a reviewed design change, not an unannounced fallback to arbitrary paths. `create_args` accepts only BASE plus the current full-label random session name and an exact four-field binding record. Device/inode/owner are strict integer values derived from the host's still-open no-follow directory FD. Unknown fields, alternate paths, negative/noninteger values and missing review acknowledgment are rejected.

Docker receives one bind to `/session`, initially **readonly** and **rprivate**. Namespace/resource settings remain private and unchanged:4e9 memory+swap,512 tasks,2CPU; no SYS_MODULE/devices/host namespace/root/socket/cgroup-tree bind was added. The host retains the FD, verifies path identity before create and before each destructive cleanup, and keeps sticky drift failure/charge preservation.

Immutable PID1 performs the session handshake before kernel/cgroup bootstrap, prepare_session, content access, chown, snapshot or cleanup. It parses exactly three unsigned decimal identity fields and a strict host mount-namespace ID; the current mount namespace must differ. It opens only the `/session` mountpoint with no-follow directory semantics, checks directory type, device/inode/UID and exact0700 mode, and requires one read-only mount record with no propagation fields. Missing, duplicate, unknown-flag, shared or slave mount records fail. A mismatched target remains RO and never reaches any session-writing/cleanup path.

Only live bootstrap may remount this already-validated bind through its **current-namespace directory FD**, using existing SYS_ADMIN and MS_BIND|MS_REMOUNT. The remount preserves every recognized non-RO mount flag; after it, the same FD identity, propagation, RW state and all remaining flags are rechecked. No global `/proc/sys` change is involved. Actual Docker mount and RW-remount compatibility remain unexecuted pending review.

The new fixed `mount-smoke` mode requires `--reviewed-mount-profile`. It uses the session owner's numeric UID, zero capabilities, default seccomp/AppArmor, the same private namespaces/fixed limits, and only the owned RO/private bind. Its immutable entrypoint checks identity and RO without remounting, reading session files, or launching k3s. The host compares exact permitted public session file names/metadata/SHA256 before and after execution and before object deletion. A mismatch retains objects and charge. Success removes the exact owned objects and releases charge after those checks. The probe is not cluster readiness, enforcement or conformance evidence.
