## Changes by finding

1. **Deletion ordering and retained scene.** `image_session` passes a cleanup gate to the actual `execute` lifecycle. After the owned container is stopped and before removing it, the gate checks the still-open directory identity and returned session state. It runs again before image removal and charge release. A validation failure is sticky for the invocation: the finally path cannot subsequently delete the image even if a pathname is restored. Full `image_session` tests replace the real directory after container start, after stop and between container/image deletion, for both smoke and bootstrap. Before-first-delete drift retains both objects; later drift retains the still-existing image. All drift cases preserve the unreleased charge at the original directory and leave the replacement empty. There is no claim that a previously deleted object can be restored or that filesystem validation and Docker deletion form an atomic transaction.

2. **Observed safe warning evidence.** The former code/deduplication function is replaced by `warning_lines`. Only complete timestamped fixed-format module-unavailable or forwarding-EROFS lines pass. Accepted output is the exact observed safe line, including timestamp, in original per-source order with duplicates retained, alongside the fixed log source. Extra fields, secret prefixes, invalid timestamp text and non-allowlisted warnings/errors fail without echoing their content. Informational text is not exported. This is observed text, not a reconstruction from codes. Success removes private data and retains only public identity plus validated observed lines.

3. **Independent containerd log.** The startup gate reads both fixed `root/private.log` and `root/agent/containerd/containerd.log`; the combined read acceptance limit is32,000,000 bytes. Every descendant component uses no-follow opens, files must be regular, FIFO opens cannot block, and reads themselves are bounded to remaining+1 rather than trusting a prior file-size snapshot. Missing logs, growth past the combined limit, unsafe links/nonregular files and unexpected warnings/errors fail. The selected [configuration source](https://github.com/k3s-io/k3s/blob/v1.36.5%2Bk3s1/pkg/agent/config/config.go#L527) sets the independent path; the selected [containerd launcher](https://github.com/k3s-io/k3s/blob/v1.36.5%2Bk3s1/pkg/agent/containerd/containerd.go#L56) redirects both streams there when debug is off. It also rotates logs, so discovery of rotated containerd history before/after the read rejects success rather than silently checking only the latest file. No rotated file is read or publicly exported. `sources.json` records fresh hashes for both pinned sources.

4. **Minor test-output noise.** The existing Docker tests capture actual guard subprocess output and assert its expected refusal text; they also capture and assert synthetic conformance output. The guard still really executes. Final covering output has test names/results only, without stray guard, fake conformance or ownership messages. No old production runc/API implementation was changed.
