## OIDC design

Concrete public API (illustrative types, not source edits):

```go
type Claims struct { Issuer, Subject string; Audience []string; ExpiresAt time.Time; Scopes []string }
type Verifier struct { /* validated immutable config + bounded JWKS cache */ }
func (v *Verifier) Verify(raw string) (Claims, error)
func (v *Verifier) VerifyContext(ctx context.Context, raw string) (Claims, error)
type TenantAdapter struct { Tokens *Verifier; Users ActiveUserLookup }
func (a *TenantAdapter) Verify(ctx context.Context, raw string) (tenant.Claims, error)
```

`Verify` creates a bounded context (5sec maximum); `VerifyContext` observes caller cancellation/deadline and a maximum5sec bound. Adapter verifies first, then queries SQL with the request context, returning only stored TenantID. Compile-time assertions cover the adapter's `tenant.Verifier` conformance. No impossible method overload. User TenantID is never decoded from token or read from payload/header. No cached positive authorization, session map, JIT user creation, or tenant creation from token.

Production config provides a single tenant-specific Entra v2 issuer, Warden API audience (API application client ID), fixed HTTPS JWKS URL, and required delegated scope `warden.access`. Multiple Warden tenants can share this configured authority, but each identity maps to exactly one Warden tenant in this minimal version. Supporting several authorities later requires separate configured issuer caches; no `common`/`organizations` wildcard issuer matching. No discovery or `jku`/`x5u` fetch derived from token content. Constructor rejects empty/partial config, userinfo/fragments/non-HTTPS JWKS URLs, and redirect-enabled client behavior. Unit tests inject a private transport/test URL through test-only construction, not a production insecure flag.

Token contract: three nonempty base64url JWT segments, maximum16KiB total (must fit server header limits), header maximum2KiB, kid1..128bytes. Only RS256, RSA2048..4096bit keys, sensible odd exponent; reject `none`, HS*, algorithm/key mismatch, unsupported `crit`, duplicate security-sensitive JSON members, malformed types, ambiguous kid/key duplicates, private key fields, unsupported key use/key_ops. Verify signature over exact encoded header.payload using stdlib crypto. No new dependency/download is needed; this deliberately narrow implementation must receive independent security review, with parser tests rather than a broad claim of general JOSE support.

Require exact `iss`, nonempty `sub`, expected `aud` string or array containing exactly configured resource among its entries, integer `exp` with `now < exp`, and integer `nbf` when supplied with `now >= nbf`. Require `exp > nbf` if nbf is present. Zero clock skew for the explicit boundary tests; injected clock drives time validation and cache TTL. Production Entra mode additionally requires v2 token and delegated `scp` containing `warden.access`; ID tokens (even matching an app audience), Graph/ARM audiences, client-credentials app tokens, and wrong scopes are rejected. OIDC parsing does not mistake `typ=JWT` for proof of an access token.

JWKS: one immutable complete keyset snapshot per configured authority; successful fetch timestamp gives exactly10min freshness, replaced atomically. At or after expiry the prior set is unusable until refresh succeeds. Never extend stale keys on failure. A successful refresh that removes a key removes it immediately; in the absence of refresh it may remain valid only until snapshot expiry. This is stricter than waiting10min after removal and satisfies removed-key rejection after expiry. Invalid/empty/duplicate-key response is not installed and does not extend TTL. If an opportunistic refresh fails, previously known keys can still be used only while their original snapshot remains fresh; unknown kid fails.

Transport: fixed configured HTTPS URL; no redirects, no token-derived endpoint, no inherited proxy by default; TLS trust defaults, connect/TLS2sec, whole request3sec, maximum1MiB body (read limit+1), maximum64keys, status200 only. One fetch in flight per verifier; waiters reuse its result. Refresh worker has its own bounded context so one canceled caller does not cancel other callers; canceled waiters return promptly. At most32waiters; no unbounded per-kid map/goroutine. Close body on every path. Context termination/shutdown releases fetch resources.

Abuse admission proposal: unknown-key refresh budget2/sec, burst2, shared across issuer; fresh-cache known keys do not consume it. A permitted unknown key immediately joins the in-flight request or triggers refresh, even if the last refresh just completed (no arbitrary5min cooldown). Rate-exhausted calls fail closed without I/O. Expired-key cache refresh has one separate bounded/coalesced path; upstream failure uses a bounded1sec backoff while denying expired tokens. This preserves normal immediate rotation while limiting attacker-generated distinct kids; controller must explicitly accept the overload behavior in decision4. Verify network count and retained map size under distinct-kid storm.

## SQL authority and SCIM lifecycle

Migration003 proposed tables, with byte-length/check constraints and server timestamps:

- `identity_tenants(tenant_id PK, issuer NOT NULL, active bool)`, created only through operator bootstrap. Existing runs are not auto-granted membership and receive no new FK that would break existing tenant strings.
- `identity_users(user_id PK generated random opaque ID, tenant_id FK, user_name, user_name_key, external_id nullable, active, deleted_at nullable, created_at, updated_at, version)`. Unique active/not-deleted username key per tenant and optional externalId per tenant; normalization deterministic and tested. Small first version can document ASCII username case folding to avoid claiming full Unicode case-insensitive normalization.
- `identity_subjects(issuer, subject, user_id FK, PRIMARY KEY(issuer,subject))`. Binding is immutable through SCIM; allow multiple known subjects for a user if explicitly bound, but any `(issuer,sub)` belongs to exactly one user/tenant. Binding transaction verifies issuer equals that user's tenant authority. Deleted identities remain tombstoned and cannot silently transfer to another user; explicit restore/rebind is outside this task.
- `identity_provisioners(credential_id PK, tenant_id FK, secret_hash bytea UNIQUE length32, expires_at, revoked_at nullable, created_at)`. A credential authorizes only Users management for its stored tenant; it cannot create tenants, change mappings, or mint credentials. Target payload cannot supply credential scope.

Active-user lookup joins identity_subjects → identity_users → identity_tenants with exact issuer/subject and active=true/deleted_at IS NULL on user and active=true on tenant. Missing row/duplicate/corrupt binding/DB error denies401. Every ordinary run API request makes this authoritative check. Deactivation returns only after SQL commit; requests beginning authorization after that commit return401 immediately, satisfying the60sec bound without sleeps. Requests already authorized before commit may finish within existing request deadline; this task does not cancel existing jobs or claim global Entra refresh-token revocation. Those semantics would require a separate decision.

SCIM administrative auth: `Authorization: Bearer <256-bit random local credential>`; strict size/format, SHA-256 digest lookup in SQL plus credential expiry/revocation and tenant active check. It is an actual secret authenticator, never a tenant name encoded as bearer. Run API cannot use it and SCIM cannot use ordinary user OIDC tokens. No DB query includes raw credential in logs. Missing/wrong/expired/revoked credential401; another tenant's user identifier404. Provisioner and tenant state are rechecked/locked within each write transaction so credential revocation cannot race a newly committed unauthorized write. Lock order is stable: tenant, provisioner, user, audit head. Read auth and resource lookup should use one statement/snapshot or bounded transaction, not stale in-memory admin authorization.

Offline operator bootstrap uses existing controlled database access; it is not exposed to callers. It accepts explicit tenant+issuer, cannot derive them from unauthenticated token claims, and emits a transactional audit event. Credential issue writes the secret once to an exclusively created0600 file under an operator-supplied already-owned0700 directory (no overwrite/symlink); DB stores only hash, expiry, ID; console/evidence receives ID/expiry only. File write failure must not leave a live credential without receipt; generate/write before insert and remove the file if SQL commit fails. Credentials last at most24h and revoke by ID. Runtime bootstrap execution requires separate approval/admission, not merely implementing CLI code.

Binding needs a previously created SCIM user, exact configured issuer, and subject obtained from a cryptographically verified custom-API access token by an approved operator workflow. Usernames/emails/externalId are display/correlation values, not authentication shortcuts. Entra `sub` is pairwise and differs from directory `oid`; the operator must not bind `externalId` as `sub` by convention. The CLI/library may validate the supplied token in memory to derive issuer/sub, never print/save it, and requires an explicit target user ID; that actual token retrieval/bind operation remains gated. No public endpoint lets a token choose a tenant or user to bind itself to.

User changes and `audit.AppendTx` share a SQL transaction. Audit event contains tenant, operation, opaque actor credential ID and user ID, old/new active/version as needed; omit tokens, hashes, private keys, and unnecessary profile PII. Audit failure rolls back the mutation. DELETE sets active=false/deleted_at, preserving identity tombstone and audit; normal GET/filter excludes it and returns404. Duplicate create409, no accidental reactivation/upsert. PATCH active=true can reactivate a deactivated but not deleted user (audited); deletion cannot be undone through PATCH. Duplicate deactivate is successful no-op with no duplicate state-change event; actual changes monotonically increment version.

Required API:

- POST `/scim/v2/Users`: core User schema, required bounded userName, optional bounded externalId, active defaults true; generates immutable ID,201 + Location/meta. Minimal selected profile fields only; never accepts password, tenant assignment, subject binding, server-generated id/meta as write authority. Do not ignore a submitted privileged mapping field silently: return400.
- GET collection: SCIM ListResponse with totalResults/startIndex/itemsPerPage/Resources, 1-based pagination; count default100/max200, support count0; deterministic order. Support only exact `userName eq "..."` and `externalId eq "..."` filters with JSON string escaping and bound SQL parameters. - PATCH same resource: PatchOp schema,1..16 operations, atomic replace/add of `active` boolean, both `path:"active",value:false` and absent-path `value:{"active":false}` forms; true supported for undeleted users. Unsupported path/mutability400 with SCIM error; no partially applied operation list.
- DELETE same resource: committed tombstone204; missing/already-deleted404.

All SCIM responses use `application/scim+json`, cache-control no-store, SCIM Error schemas/status for errors, fixed generic401/500 messages, no database diagnostics. Body64KiB, userName/externalId max256bytes, filter max1024bytes, strict trailing-data and duplicate-member handling; operation count/body overflow413 or defined400 as appropriate. HTTP request timeout10sec consistent with existing API, header bounds retained, unsupported method405 with Allow.
