# Pinned ACK/stdin lifecycle rationale

These are upstream v28.0.0 sources read for the round4 correction. They are not a source/binary match for the previously observed installed Docker29.9.1, and no actual container was created or started in this round.

1. [Docker CLI option parsing](https://github.com/docker/cli/blob/v28.0.0/cli/command/container/opts.go#L320-L339) sets attached stdin for `--interactive` and, without explicit `--attach` options, selects stdout and stderr. [Config construction and finalization](https://github.com/docker/cli/blob/v28.0.0/cli/command/container/opts.go#L595-L676) selects `OpenStdin=true`, all three Attach booleans true and `StdinOnce=true`. The existing create command already requests this configuration. No new flags are needed.
2. [Docker CLI create](https://github.com/docker/cli/blob/v28.0.0/cli/command/container/create.go#L85-L120) uses that parser; [createContainer](https://github.com/docker/cli/blob/v28.0.0/cli/command/container/create.go#L190-L253) sends the resulting Config to ContainerCreate. Strict local inspection now requires these exact boolean values, `Tty=false`, and the existing fixed trusted entrypoint/mode/user.
3. [Docker Engine API v1.48 schema](https://github.com/moby/moby/blob/v28.0.0/api/swagger.yaml#L1250-L1262) defines StdinOnce as closing container stdin after one attached client disconnects. The v1.56 rendered reference was also opened but did not expose its schema text to the browser tool; the pinned schema is the directly inspected contract here.
4. [Docker CLI start](https://github.com/docker/cli/blob/v28.0.0/cli/command/container/start.go#L66-L164) uses its interactive option plus Config.OpenStdin for attach stdin, explicitly attaches both outputs, establishes attach before start, and waits for the attachment and container exit. Existing non-TTY signal forwarding is unchanged.
5. [Docker CLI hijack input](https://github.com/docker/cli/blob/v28.0.0/cli/command/container/hijack.go#L133-L163) calls CloseWrite after input copying ends. Its [stream coordinator](https://github.com/docker/cli/blob/v28.0.0/cli/command/container/hijack.go#L37-L59) continues waiting for output after input completion. Closing the Python child's stdin therefore requests attach-input EOF while retaining output processing.
6. [Moby daemon attach](https://github.com/moby/moby/blob/v28.0.0/daemon/attach.go#L40-L47) maps Config.StdinOnce to CloseStdin. The [non-TTY StdinOnce path](https://github.com/moby/moby/blob/v28.0.0/daemon/attach.go#L175-L183) also waits for container termination before returning.
7. [Moby stream copy](https://github.com/moby/moby/blob/v28.0.0/container/stream/attach.go#L58-L89) closes container stdin when CloseStdin is true and TTY false. Otherwise it closes the attached output pipes, leaving the daemon-owned container-input writer open. This explains why valid ACK bytes alone cannot complete the unchanged Go ACK+EOF receiver under the old required false configuration.

The native Python fixture models these input/output lifetimes with real pipes and a bounded receiver stand-in. It does not execute Moby or Go, nor prove device enforcement. Installed-version behavior, the actual receipt, BPF composition, TUN denial and owned-cgroup disappearance still require controller-only execution after independent review and fresh source-bound preparation/admission.
