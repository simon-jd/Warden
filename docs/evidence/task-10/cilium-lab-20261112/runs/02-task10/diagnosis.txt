# One query from diag-dns-runc (warden-probe net q1,dns,A,warden-egress.warden-system.svc.cluster.local):
# the TPROXY counter went 22 -> 23, Ip:InReceives +307, Ip:InDelivers +306, no error counter moved

## The drop: the reverse-path check of the TPROXY'd packet
$ ip route   # node: the pod CIDR is behind cilium_host; ip rule 9: fwmark 0x200/0xf00 lookup 2004; table 2004: local default dev lo
$ cat /proc/sys/net/ipv4/conf/all/src_valid_mark   # node netns, inherited from the host's (host: 1)
1
$ ip route get 10.42.0.254 from 10.42.0.225 iif lxc491de4a42698 mark 0x200
RTNETLINK answers: Invalid argument
# With src_valid_mark=1 the kernel validates the source with the packet's mark: the reverse
# lookup of 10.42.0.225 with mark 0x200 hits rule 9 -> table 2004 -> a local route, which is
# not accepted as a source (accept_local=0), so the packet is a martian and is dropped
# (fib_validate_source; martian drops have no SNMP counter).

## The node's own setting set to 0 (per-netns; the host's stays 1)
$ docker exec warden-k3s-gvisor sysctl -w net.ipv4.conf.all.src_valid_mark=0
net.ipv4.conf.all.src_valid_mark = 0
$ cat /proc/sys/net/ipv4/conf/all/src_valid_mark   # host
1
$ ip route get 10.42.0.254 from 10.42.0.225 iif lxc491de4a42698 mark 0x200
local 10.42.0.254 from 10.42.0.225 dev lo table 2004 mark 0x200
    cache <local> iif lxc491de4a42698
